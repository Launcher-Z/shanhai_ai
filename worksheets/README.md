# 学习札记维护

4.1使用`lesson-4-task-1.json`，只有一段异兽测试结果表。`animal_predictions`的`columns`、`rows`指定固定四类和四图，16个数值字段沿用文字答案，提交时核对0—100和每行合计100（`sum_tolerance: 0.2`）；学生手填，无自动代入，无审核，提交变绿。2.2未配置固定行列时仍保留原两类名称、九图及摄像头选填行。

一项活动对应一份 UTF-8 JSON，文件名须与 `shanhai/courses.py` 的活动 ID 一致。例如，第 6 课活动一使用 `lesson-6-task-1.json`。每个 `sections` 分段与实验中的一个子活动对应，名称和顺序一致。此目录由后端读取，不放进 `static`，避免标准答案提前发给学生。

## 存储边界

遵循根目录 [AGENT.md 的数据存储规范](../AGENT.md#实验与学习札记的数据存储规范)：实验状态保存在学生浏览器本地，札记答案、首次成绩、订正和审核保存在服务器数据库；活动完成与圈色只依据服务器札记，不依据本地实验记录。

札记暂存与正式提交必须分开。无感暂存只按草稿保存，沿用 `revision` 校验，不能自动判分或解锁下一步；正式提交由学生主动触发。右上角重置不得删除或覆盖任何服务器札记记录，当前页面内尚未暂存的札记输入也应保留。

札记已支持无感暂存：输入停顿约1秒后保存草稿，保留手动暂存；正式提交仍由学生主动操作。1.2／1.3作品仍须主动提交，不自动上传。第6课三项实验与第7课实验支持本地持久保存与恢复，第6课恢复后自动演示保持暂停。

实验表格使用 `type: "text"` 与 `record_table.fields` 定义行，浏览器显示位移输入和4行表格，服务器沿用可读文字答案保存。`experiment_record: true` 可主动带入同一位移下的实验快照；暂存允许部分填写，提交校验完整性、整数位移及0—100%的范围。

## JSON 格式

```json
{
  "activity_id": "lesson-6-task-1",
  "version": 2,
  "title": "图像数字运算 · 学习札记",
  "intro": "边做实验，边记下发现。",
  "sections": [
    {
      "id": "pixels",
      "step": 0,
      "title": "观察与记录",
      "optional": false,
      "questions": [
        {
          "id": "channel-count",
          "type": "number",
          "prompt": "实验中的一个 RGB 像素，用几个通道数值记录颜色？",
          "required": true,
          "answer": 3,
          "explanation": "R、G、B 分别记录红、绿、蓝。"
        },
        {
          "id": "observation",
          "type": "text",
          "prompt": "记下一处具体观察，并说明原因。",
          "required": true,
          "review": true,
          "max_length": 1200
        }
      ]
    }
  ]
}
```

| 题型 `type` | 配置 |
| --- | --- |
| `single` 单选 | `options` 为 `[{"value":"a","label":"选项文字"}]`；`answer` 为某个选项的字符串 `value` |
| `multiple` 多选 | `options` 同上；`answer` 为字符串数组。顺序不限，须全部选对且不多选 |
| `number` 数值 | `answer` 为 JSON 数字；默认精确匹配，可用 `tolerance` 指定绝对误差范围 |
| `text` 文字记录 | 不设 `answer`；`review` 默认为 `true`，表示需要教师审核；`max_length` 默认 1200 |

固定答案题全部设为 `required: true`，各题等权，正确率为“首次答对题数 ÷ 固定答案题总数”。主观题不计入正确率。选做记录使用 `required: false, review: false`，留空不影响完成。

题目 ID 和分段 ID 在同一份学习单中必须唯一，发布后避免更改。`step` 是对应实验步骤的零起始序号，必须从 0 连续排列。`optional: true` 表示选做分段，不计入进度、评分或审核；选做分段仅放不需审核的文字记录。

调整题干、答案或评分规则时递增 `version`。学生第一次暂存或提交时会保存该版学习单快照；正在填写、已提交的记录继续使用原版，新开始的记录使用新版，避免中途改题影响成绩。从原整张提交版本升级时，系统按稳定题目 ID 重新分组，保留原题、草稿和首次成绩；原来已经整张提交的记录按全部分段已提交处理。

## 作答和圈色

1. 首次进入只开放第一个子活动及其札记；后续可看名称，题干和答案均不发送。未解锁的分段不能通过接口直接暂存或提交。
2. “暂存本段”只保存当前段，不增加进度。“提交本段”检查本段必填项；首次有效提交后立即开放下一步实验和对应札记，不要求答对、完成订正或等待教师审核。已开放步骤可以随时回看。
3. 墨痕进度条只统计“已首次提交的必做段数 / 必做总段数”，不表达正确率、审核结果或优秀程度。订正、驳回均不会回退进度或重新上锁，选做不计入分母。
4. 各段首次提交保存原始答案和成绩。答错的固定题可订正一次，其余题锁定；第一次错误不返回标准答案或解析。可以继续后面的实验，再回来订正。
5. 订正正确显示解析；仍错则展示标准答案与解析，固定题作答流程结束。订正不会覆盖首次成绩。
6. 所有必做段首次提交，且固定题订正流程结束后，需要审核的札记统一进入教师评阅。教师驳回须指定文字题并写修改建议，仅选中的题重新开放，重新提交后再次锁定。未被驳回的已审核题继续锁定。
7. 所有必做段流程结束，且所有需审核记录通过后，活动才算完成。因此进度 100% 时，活动可能仍是待订正、待审核或已驳回，活动圈保持红色。
8. 完成为绿圈；首次固定题正确率 ≥85% 且完成，为金圈。只有主观题的学习单由教师选择普通通过或优秀通过。
9. 活动圈和札记入口同步；一课全部必做活动完成才为绿圈，全部必做活动优秀才为金圈；整卷同理，包含尚未开放的课时。整项选做不影响基础课时与整卷圈色，不把“当前已开放部分完成”当作整卷完成。

自动暂存、手动暂存和每段的首次提交状态写入 SQLite，可刷新或重新登录后继续。输入期间串行合并保存，切换子活动、关闭浮纸或切换活动仍处理待存草稿；请求期间的新输入不被旧响应覆盖。断网保留页面输入并提示失败，重新联网可重试；版本冲突保留输入、不覆盖服务器，须先复制需要的内容再主动重新读取。离开页面仍有未保存内容时浏览器提醒。

## 数据接口

- `GET /api/worksheets/<activity_id>`：读取学生自己的学习单、草稿、反馈和锁定状态。
- `POST /api/worksheets/<activity_id>/save`：暂存指定分段。
- `POST /api/worksheets/<activity_id>/submit`：指定分段的首次提交、一次订正或驳回后重交，由服务端状态决定。
- `GET /api/learning/progress`：读取当前学生的活动状态，页面每 15 秒及重新获得焦点时刷新。
- 教师入口：`/teacher/worksheets`，可按班级和状态筛选并评阅。

POST 使用 JSON，`X-CSRF-Token` 请求头取自页面的 `csrf-token` meta：

```json
{
  "revision": 0,
  "section_id": "pixels",
  "answers": {"channel-count": "3", "observation": "我观察到……"}
}
```

`section_id` 使用分段 ID；`answers` 只能包含当前分段的回答。单选、数值、文字回答均为字符串，多选为字符串数组。`revision` 使用上次 GET 或保存返回的整数；服务端拒绝旧版本写入，避免双击提交和多标签页互相覆盖。

响应中的每段含 `id`、`step`、`optional`、`unlocked`、`submitted`、`status`、`can_edit`；未解锁的 `questions` 为空。题目含 `editable`；满足揭晓条件后才包含 `answer`、`explanation`。`flow` 含必做 `submitted`、`total`、`percent` 及各段元数据，控制实验和札记同步解锁。

`progress` 含 `status`、`label`、`completed`、`excellent`、`ring`、`revision` 与 `flow`，前端直接使用，不自行重算成绩。`first_correct` 为已提交固定题的首次答对题数，`objective_total` 为整张札记的固定题总数；流程进度条不使用这些成绩字段。

## 验证

项目环境：`E:\Anaconda\envs\shanhai-ai\python.exe -m unittest discover -s tests -v`。

浏览器完整流程：`E:\nodejs\node.exe tests/test_worksheets_browser.cjs`。先用 `SHANHAI_BROWSER_MODULES` 指定已有 Playwright 的 `node_modules`；可用 `SHANHAI_BROWSER_EXE` 指定浏览器、`SHANHAI_PYTHON` 指定已确认的项目环境。测试使用独立临时数据库和两个浏览器会话，截图保存在 `output/worksheets/`，不读取实际课堂数据。

核心知识点：用分段 ID 对齐实验与札记；首次提交决定解锁和流程进度，订正与审核决定活动完成；后端统一保存状态，前端呈现并同步两个视图，避免把“进度”“完成”“优秀”混成一个值。
